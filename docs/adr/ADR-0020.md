# ADR-0020: Architecture governance and decision freeze

**Status:** Accepted  
**Date:** 2026-08-16
**Accepted:** 2026-08-27

## Context

Documentation-first design loses value if implementation silently changes accepted decisions.

## Decision

After M0 owner acceptance, freeze the architecture baseline. Material changes require a new or superseding ADR and traceability updates.

## Consequences

The repository preserves why architecture changed instead of rewriting history.

## Reconsider when

Reconsider only when operating evidence, product scope, plugin capability, security/privacy requirements, cost, or deployment constraints materially change the assumptions behind this decision.


## Freeze Activation

M0 was owner-approved on **2026-08-27**.

Effective immediately:
- this documentation package is the implementation design authority;
- implementation work must conform to accepted requirements and ADRs;
- material architectural changes require a new ADR or an ADR that explicitly supersedes an accepted decision;
- implementation details may evolve without an ADR only when they do not change accepted architecture, product scope, security boundaries, data authority, or milestone obligations.
